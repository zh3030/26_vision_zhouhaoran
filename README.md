
# RoboMaster 能量机关视觉识别 (Buff Detector)

## 简介

本项目用于 RoboMaster 比赛中能量机关（俗称“大风车”）的实时检测与状态识别。基于 OpenCV 实现，能够：

- 定位能量机关的 **中心 R**；
- 提取 **待激活圆** 与 **已激活圆**；
- 将各个扇叶轮廓分配至对应扇区；
- 根据遮挡情况提取扇叶角点；
- 输出各部件坐标、角度以及 ROI 信息，供后续预测与瞄准使用。

代码支持 CPU 运算，并尝试使用 OpenCL 加速预处理步骤，若 GPU 环境不可用将自动回退至 CPU。

## 依赖

- C++17 或更高版本编译器
- [OpenCV](https://opencv.org/) 4.x（需包含 `core`, `imgproc`, `highgui`, `videoio` 等模块，若使用 OpenCL 加速需启用 `ocl` 模块）
- 操作系统：跨平台（Windows / Linux）

## 编译与运行

```bash
mkdir build && cd build
cmake .. -DENABLE_TEST=ON -DENABLE_TIME=OFF
make -j$(nproc)
./buff_detector
```
或直接运行run.shell

 - 注：在运行时可通过命令行传入视频路径，否则默认使用当前目录的"test1.mp4"视频文件，若需使用摄像头可更改`cv::VideoCaptrue`

程序将从当前目录下的 `../test1.mp4` 读取视频，并输出处理后的视频 `output.avi`。

### 编译选项（宏定义）

可在 CMakeLists.txt 或命令行中定义以下宏：

| 宏           | 作用                                                         |
| ------------ | ------------------------------------------------------------ |
| `BUFF_TEST`       | 在图像上绘制检测结果（中心、角点、标签等），调试时建议开启。 |
| `BUFF_TIME`       | 输出各个处理阶段的耗时（毫秒），用于性能分析。               |
| `ADD_POINTS` | 在 `buff` 对象中保存各扇区的中心点坐标，通过 `get_points()` 获取。 |
| `BUFF_WRITE`      | 保存处理后的视频


## 算法流程

`buff::run()` 是核心处理流水线，对单帧图像执行以下步骤：

1. **预处理** (`subImage`)  
   分离 RGB 通道，计算 `R - B` 差值图，二值化，高斯模糊，膨胀。支持 OpenCL 加速并自动回退 CPU。

2. **查找轮廓**  
   `cv::findContours` 以 `RETR_TREE` 模式提取所有轮廓及其层次关系。

3. **轮廓初始化** (`initializeContours`)  
   过滤面积过小的轮廓，计算每个轮廓的面积、周长、圆度、长宽比、中心点、父轮廓数量、子轮廓数量。

4. **提取中心 R** (`extractCenterR`)  
   在无父轮廓的最外层轮廓中，寻找长宽比接近 1 且面积最小的轮廓，作为能量机关的旋转中心。

5. **提取待激活圆** (`extractInactiveCircleCenter`)  
   在剩余轮廓中查找子轮廓数量 > 1 且圆度足够高的轮廓，记录其相对于 R 的角度作为参考零位。

6. **提取已激活圆** (`extractActivatedCircleCenter`)  
   对圆度足够、面积足够、无父轮廓且子轮廓数 ≤ 1 的轮廓，根据其角度分配至对应扇区索引。

7. **轮廓分组** (`processContours`)  
   将余下的轮廓（扇叶部分）按角度距离分配到最近的已有扇区，并剔除与现有圆心距离过近的重复轮廓。

8. **角点提取** (`findCorners`)  
   根据扇区内的轮廓数量和状态调用不同策略：
   - **无遮挡扇叶**：直接对扇叶轮廓求凸包并多边形逼近。
   - **部分遮挡扇叶**：合并扇区内所有轮廓（除圆外）后求凸包与逼近。
   - **待激活扇叶**（基于内轮廓中心）：利用内轮廓中心生成凸包并外推角点。

9. **更新状态**  
   更新成员变量：中心坐标、角度队列、ROI 裁剪区域等，供外部调用和后续帧使用。

## 输出与接口

`buff` 类提供以下公共接口：

| 方法                             | 返回值                                       | 说明                                                         |
| -------------------------------- | -------------------------------------------- | ------------------------------------------------------------ |
| `get_center()`                   | `const cv::Point&`                           | 当前帧识别的旋转中心 R 坐标。                                |
| `get_div_data()`                 | `const std::vector<std::vector<buff_data>>&` | 分组数据，索引 0=R，1=待激活圆所在扇区，2~5=各扇叶（含圆与叶片）。 |
| `get_angle_info()`               | `const std::deque<AngleData>&`               | 历史角度与距离信息，可用于角速度计算。                       |
| `get_roi_info()`                 | `const RoiData&`                             | 当前帧计算出的 ROI 裁剪信息（左上角坐标与半径）。            |
| `get_points()` (需 `ADD_POINTS`) | `const std::vector<cv::Point>&`              | 各扇区中心点坐标（R, 待激活圆, 已激活圆…）。                 |

`main.cpp` 示例中演示了如何获取 ROI 并在后续帧中仅处理裁剪区域，以提升速度。

## 注意事项

- **视频输入**：默认从 `../test1.mp4` 读取，请确保文件存在或修改路径。视频帧率和尺寸会自动获取，输出 `output.avi` 使用相同参数。
- **ROI 自适应**：前 5 帧会使用全图进行初始化，计算合适的 ROI 裁剪半径，之后仅处理 ROI 区域。若目标移出 ROI，可能需要重置或扩大边界。
- **光照与颜色**：预处理基于 R 与 B 通道差值，适用于 RoboMaster 能量机关的红/蓝灯效。若场景颜色变化，需调整 `threshold_value` 或替换为其他颜色空间。
- **性能**：在处理全图时耗时较高，ROI 裁剪后可大幅降低。若仍需加速，可开启 `TIME` 宏查看各步骤耗时，并针对性优化。
- **OpenCL 支持**：代码自动检测 OpenCL 可用性，若失败会输出错误信息并回退 CPU，不影响运行。确保 OpenCV 编译时开启了 OpenCL。
